# 2026-09 成熟化修复与验收

本次更新完成 12 项审计缺陷修复，并收录已经验证的领域拆分、回归测试、质量证据门禁和发布工具。版本保持 0.19.0；核心 HTTP 保存契约升级为 v2。本文记录本地验收结果，GitHub Actions 的执行结果以对应提交的检查为准。

## GitHub 单仓集成

`novel-writer` 和 `mogao-tauri` 在本仓库共享同一个 Git 提交。根目录工作流一次检出完整源码；来源记录支持 Git 子目录，只计算各项目自身文件，排除输出和缓存。发布 manifest 与 CI 使用一致的目录排除规则。不需要为两个子目录创建独立远端或配置兄弟仓库 token。

源码更新不修改仓库内历史 `mogao-tauri/release/ui` 快照。新候选由构建流程生成，不将 EXE、个人配置、真实 Vault、密钥或运行缓存提交到源码仓库。

## 兼容边界与剩余验收

旧 HTTP 写客户端必须升级以提交版本条件；缺少版本返回 428，陈旧元数据/文件写入返回 409。章节冲突继续通过保存警告和双版本界面处理。详见 [后端契约](../novel-writer/docs/BACKEND-CONTRACT.md)。

内容版本保护不等于多文件断电事务；生成的元数据镜像仍需按导入/同步流程处理。真实模型盲评、安装/卸载和不同机器的原生对话框/WebView2 验收仍需执行。

候选生产引擎保持 **hold，默认关闭**。确定性评估 fixture 只验证评估流程，不能证明文章质量改善。正式启用前应完成 [质量评估协议](../novel-writer/docs/QUALITY-EVALUATION.md) 中的真实模型配对样本和人工盲评。

详见 [执行计划](../novel-writer/docs/MATURITY-REMEDIATION-2026-09.md)、[架构](../novel-writer/docs/ARCHITECTURE.md) 与 [发布说明](../mogao-tauri/docs/RELEASE.md)。
