# Inkwell Frontend V1 · 墨色编辑台全面改造 Goal

## 1. 目标与设计立场

本 Goal 将 Inkwell 从“功能按页面堆叠的工具集合”重构为面向长篇作者的“墨色编辑台”。核心不是表面换肤，而是让作者在任何时刻都能快速回答：

1. 我正在写哪一本书、哪一章？
2. 本章任务和不可违背的约束是什么？
3. Inkwell 为当前请求装配了哪些故事记忆？
4. 生成、审查和章后交接现在进行到哪一步？
5. 是否存在需要作者处理的连续性风险？

视觉方向固定为“克制的编辑部纸墨美学”：温暖纸面、清晰墨色、单一朱砂强调、低噪声质感、严格的信息层级。拒绝通用 SaaS 仪表盘、全屏胶囊按钮、紫色渐变、无意义玻璃拟态和混用 Emoji 图标。

产品记忆点为“叙事脉络条”：在正文上方持续显示任务、POV、开放伏笔、连续性风险和章后交接状态，并可直接跳转到相应检查器。

## 2. 已确认的现状基线

- 1280×720 下，写作区同时被 200px 书库、220px 章节和 300px 任务栏占用，正文约 560px。
- 1024×768 下正文约 424px；顶栏和库状态栏合计约 193px。
- 顶栏同时包含六个模式、书籍选择和大量低频文件操作，视觉优先级失真。
- 浅色主题组件仍大量使用硬编码深色背景，侧栏、正文和日志形成割裂的混合主题。
- “续写/生成”和“按任务写/续本章”重复表达主要动作。
- 连续性问题、上下文预算、故事记忆、钩子与实体状态主要以原始文本展示。
- `<860px` 仅把侧栏堆叠到正文上下方，不能满足 1024px 左右的桌面窗口使用。
- Google Fonts 是运行时网络依赖，离线桌面环境会退化。

## 3. 范围、不变量与风险控制

### 3.1 正式源与同步目标

- 只在 `novel-writer/` 修改正式前端源。
- 验收后同步到 `mogao-tauri/src-tauri/ui-embed/` 和 `mogao-tauri/release/ui/`。
- 继续使用当前原生 HTML/CSS/JavaScript，不引入 React、Vue 或大型运行时。

### 3.2 不变量

- 不改变书库目录、项目 JSON、章节正文、Canon、RAG、连续性审查的数据语义。
- 第一阶段尽量保留现有 DOM ID；需要移动控件时只改变容器和样式，不改变事件所依赖的 ID。
- 不覆盖用户正文，不改变保存、生成、停止、交接、快照和迁移的权限边界。
- 生成锁定状态必须继续阻止危险切换，但要用可理解的界面解释原因。
- 所有主题都必须使用语义 Token；组件规则不得偷偷写入只适用于某一主题的黑色背景。
- 无网络、无字体服务、无 embeddings 时界面仍完整可用。

### 3.3 版本与迁移

- 目标版本为 `0.10.0`。
- 增加 UI 状态 schema：活动一级入口、故事二级入口、书库抽屉、检查器标签、专注模式和可选面板宽度。
- 兼容旧的 `uiState.panels`；旧折叠状态首次加载时迁移到新的导航/抽屉状态。

## 4. P0 · 应用框架与写作核心

### P0-1 统一视觉 Token

- 重建背景、表面、纸张、文字、弱文字、边线、强调、成功、警告、危险、焦点环、阴影和层级变量。
- 重新实现 `soft-paper`、`ink-night` 和 `qing-jian`，保证同一主题内部一致。
- 正文、侧栏、弹窗、输入框、日志、代码块和选择态全部只引用语义 Token。
- 圆角收敛：普通控件 8px、卡片 10–12px；胶囊只用于状态和分段选择。
- 纹理只作用于最外层背景，透明度不超过 3%，不得降低正文可读性。

验收：浅色主题不存在意外黑色侧栏；普通正文对比度不低于 4.5:1；焦点和状态不只依赖颜色。

### P0-2 52px 全局栏

- 顶栏仅保留品牌、当前书籍、书库入口、四个一级入口、全局搜索、书库工具和设置。
- 将新建书、导入示例、打开目录、重载、迁入、导出、库路径等低频动作收进“书库工具”菜单。
- 连接/保存状态采用小型状态点和文字，错误状态可点击查看详情。
- 移除独立的常驻 vault bar，将其信息迁入顶栏和工具菜单。
- 顶栏不得换成两行；1024px 下隐藏品牌副标题和次要文字，但保留可访问名称。

验收：1280px 与 1024px 下顶栏保持单行，常驻高度不超过 58px。

### P0-3 四入口信息架构

- 一级入口固定为：写作、故事、资料、分析。
- 写作映射现有 `write`。
- 故事包含策划、主线与任务、人物关系三个二级入口，映射 `pipeline/control/graph`。
- 资料映射 `workspace`，同时承载书库、文件、搜索和快照。
- 分析映射 `analyze`。
- Ctrl/Cmd+1–4 依次切换四个一级入口；故事内部使用 Alt+1–3 或点击二级导航。
- 正确维护 `aria-current`、`aria-selected` 和生成锁定提示。

### P0-4 书库抽屉

- 永久移除占据内容宽度的 200px 全局书库栏。
- 原书库列表改为左侧抽屉，宽度约 300px；通过当前书籍按钮打开。
- 支持遮罩点击和 Escape 关闭；切换书籍后自动关闭。
- 抽屉内保留筛选、新建、快照和快照列表。
- 无书籍时显示三个明确入口：新建书、打开库、导入示例。

### P0-5 写作布局

- 桌面大屏布局：章节栏 220px、正文弹性区域、检查器 300px。
- 1200px 以下检查器变为右侧抽屉，不再挤压正文。
- 1050px 以下章节栏也可按需抽出；正文始终处于第一视觉层级。
- 正文内容列控制在 760–820px，保持适合中文长文的行宽。
- 1280px 默认正文可用区域不低于 700px；1024px 不低于 680px。
- 新增专注模式，隐藏一级导航、章节栏和检查器，只保留正文、章节状态与退出入口。

### P0-6 章节头与叙事脉络条

- 章节头显示标题、字数、保存状态、章后交接状态和更多操作。
- 脉络条显示本章任务、POV、开放伏笔数量、连续性风险数量、上下文健康度。
- 每一项是可访问按钮，可打开右侧对应检查器。
- `blocker/major` 风险必须显著但不覆盖正文；无风险时显示克制的成功状态。
- 空章节、未绑定任务、待交接、索引过期均有不同文案。

### P0-7 统一 AI Composer

- 将人工指令和生成动作收敛为底部 Composer。
- 只保留一个主要 CTA，标签随模式变化：按任务写本章、从当前位置续写、重写选区、根据批注修订。
- “本章→摘要+关系”迁移到章后状态/更多操作，不再与写作主动作并列。
- 生成时展示四阶段：装配记忆、请求模型、连续性审查、章后交接。
- 停止按钮只在生成期间出现；失败时保留原稿和可重试入口。

## 5. P1 · 连续性与故事管理体验

### P1-1 右侧故事检查器

- 三个主标签：本章任务、连续性、故事记忆。
- 本章任务使用结构化字段显示目标、冲突、节拍、必须、禁止、钩子和任务状态。
- 连续性问题使用问题卡显示严重度、类型、摘要、正文证据、前文/Canon 证据和建议。
- 保留“已处理/忽略/局部修复”操作，并明确写入状态。
- 故事记忆显示人物状态、时间线、开放伏笔和相关 Canon；支持跳到故事中心。
- 原始 token/块级 manifest 放在“技术详情”折叠区，默认不显示工程日志。

### P1-2 上下文健康卡

- 将 `ctxMeter` 的原始多行文本拆成预算进度、Canon 数量、RAG 命中、裁剪、交接和降级状态。
- 预算使用分为正常、接近上限和已裁剪三级。
- RAG 失败、零命中、索引过期和严格阻断必须使用不同状态和解释。
- 保留可复制的原始 Manifest，便于高级用户调试。

### P1-3 故事中心

- 策划、主线、人物关系三个现有页面增加统一二级导航和一致页面头。
- 主线侧栏中的卷脊柱、故事线、Canon、摘要、伏笔、风险、实体状态改为折叠分组或卡片，不再形成七段连续原始文本。
- 故事概览优先显示当前进度、下一任务、开放伏笔、高风险问题、主要人物位置和最近状态变化。
- 任务表在宽屏使用表格，窄屏变卡片；状态和操作列明确。
- Canon、伏笔、连续性问题支持类型/状态筛选和证据章节显示。

### P1-4 空状态、错误状态与首次路径

- 分别实现：本地服务未连接、无书库、无书、无任务、无章节、无正文、无检索结果、生成失败、审查失败、交接失败。
- 空状态必须包含下一步动作，不能只显示“尚无数据”。
- 本地服务离线时明确说明浏览器缓存模式的能力边界。
- 错误信息不使用仅工程人员可理解的异常字符串作为主文案。

## 6. P2 · 设置、分析与精修

### P2-1 设置重组

- 设置分组为：外观、模型连接、写作、连续性、检索、高级。
- 普通模式只显示常用选项；Base URL、token 预算、Top-K、embeddings 等进入高级区域。
- 每个严格策略提供结果导向说明，而不是只显示内部术语。
- 测试连接显示进行中、成功、失败和可操作建议。

### P2-2 资料工作区

- 文件树工具使用统一图标与危险操作样式。
- 工作区编辑/分栏/预览改为标准分段控件。
- 搜索结果按正文、人物、Canon、伏笔和其他文件分组。
- 快照恢复对话框明确展示时间、文件数量和覆盖风险。

### P2-3 分析工作台

- 统一分析工具栏、输入区、进度、报告和人物/章节侧栏。
- 运行状态翻译为作者语言，步骤化显示识别、分析、聚合、完成。
- 报告默认显示摘要视图，原始文本/JSON 放入高级视图。
- 关系图、人物档案和时间线共享选中实体状态。

### P2-4 图标、动效与细节

- 使用内联 SVG 或 CSS mask 形成统一 18px/20px 线性图标，不混用 Emoji。
- 页面进入采用一次 160–220ms 的轻量层级动画；按钮反馈 120–160ms。
- 支持 `prefers-reduced-motion`。
- hover、active、focus、disabled、busy、danger 状态完整。
- 浏览器离线时字体回退仍保持稳定排版；优先复用仓库资产，无法安全加入字体文件时移除外部字体请求并使用可靠本地栈。

## 7. 可访问性、响应式与性能

- 所有可折叠区有 `aria-expanded`，标签页有 `role=tablist/tab/tabpanel`。
- 可用 Tab 键完成一级导航、选章、输入指令、生成、停止和保存。
- `:focus-visible` 在三个主题下均清晰。
- 100%–200% 缩放下不遮挡主要操作，不产生页面级横向滚动。
- 生成、审查和保存状态均提供文字/图标，不只依赖颜色。
- 1024×768、1280×720、1440×900、1920×1080 为必测尺寸。
- 三个主题至少覆盖写作、故事、资料、设置和弹窗视觉回归。
- 不引入大型依赖；静态资源总增量保持克制，启动不得等待远程字体。

## 8. 实施顺序

1. 建立前端基线检查、视觉尺寸数据和 UI 状态迁移策略。
2. 完成 Token、基础控件、图标和主题一致性。
3. 重构 52px 顶栏、四入口导航、书库抽屉与工具菜单。
4. 重构写作布局、章节头、叙事脉络条和 Composer。
5. 实现结构化任务、连续性和故事记忆检查器。
6. 重构故事中心、资料、设置和分析页面的层级与空状态。
7. 完成键盘、ARIA、焦点、动效和四档响应式适配。
8. 更新版本与文档，同步三套 UI，运行 Node/Python/Rust/CI 和 Release 验证。

## 9. 自动化与人工验收

### 自动化

- 新增前端结构测试：四入口、书库抽屉、叙事脉络条、统一 Composer、设置分组和 ARIA 属性。
- 新增纯函数/DOM 行为测试：一级模式映射、健康状态分类、风险计数、面板迁移。
- 保持现有 Node、Python、Rust 测试全绿。
- 继续运行版本一致性、26 文件 UI 同步和 release verification。

### 浏览器视觉验收

- 逐页检查写作、故事三个子页、资料、分析、设置。
- 检查 1024、1280、1440、1920 四档布局。
- 检查三主题，不允许浅色主题出现黑色孤岛。
- 检查无书、无任务、生成中、审查风险和严格阻断状态。
- 检查浏览器控制台无新增错误，交互不会丢失正文。

## 10. 完成定义

只有同时满足以下条件才可关闭 Goal：

- P0 全部完成，P1/P2 中列出的作者可见界面全部落地。
- 1280px 正文默认可用区域不低于 700px，1024px 不低于 680px。
- 顶栏单行且不超过 58px；书库不再永久占据内容宽度。
- 作者无需阅读原始日志即可理解任务、风险、预算、RAG 和交接状态。
- 每个主要页面只有一个视觉主操作；重复的写章 CTA 已消除。
- 三主题保持一致并通过对比度、焦点和缩放检查。
- 保存、生成、停止、审查、修复、交接、快照和迁移行为回归通过。
- 自动化测试、UI 同步、版本检查、Release 构建和发布校验全部通过。
