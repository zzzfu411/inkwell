# Inkwell 无状态长篇写作一致性闭环 Goal

## 1. 目标

面向 `gemini-3.6-flash` 的无状态写作调用：每次新文章/新章节都只发起一次全新聊天请求，不依赖服务端会话历史；由 Inkwell 在同一本书内持久化、检索、装配、校验并回写故事记忆。

本 Goal 的完成标准不是“提示词里出现了若干连续性字段”，而是形成可验证的闭环：

`持久化事实 → 写前检索与装配 → 生成 → 连续性审查 → 必要修订 → 章后交接 → 更新记忆与索引 → 下一章`

## 2. 范围与不变量

- 正式实现源位于 `novel-writer/`，完成后同步到 `mogao-tauri/src-tauri/ui-embed/` 与发布 UI。
- 保持 OpenAI-compatible `/chat/completions` 与现有 `gemini-3.6-flash` 配置兼容。
- 不依赖 Gemini conversation/session ID；每一次写作、摘要、审查都是独立请求。
- 不引入必须联网的向量数据库或大型框架；无 embeddings 时仍可工作。
- 不覆盖用户已有正文；自动修订必须可关闭、可追踪，并优先采用局部修复。
- 同一本书内部共享记忆，不在不同书目之间泄漏正文或设定。
- 中断后可安全续跑，不得重复叠写已完成正文。

## 3. 风险分级

### P0：正确性与数据闭环

#### P0-1 Canon 类型化比较

现状：`valuesLooselyEqual` 使用字符串互相包含判断，可能把 `5级/15级`、`50万/150万` 误判为相同。

实施：

- 新增值归一化器，区分纯文本、数值+量词、百分比、等级/层级、时间和名称。
- 数值事实比较采用解析后的数值、单位和修饰词；禁止用裸 substring 判断数字相等。
- 文本事实只允许明确的尾缀扩展白名单，如 `50万` 与 `50万人`。
- 为“合法变化”提供显式策略：静态事实保持同 key 锁定；动态事实允许版本、时间戳或作者确认更新。
- 冲突必须记录原值、新值、章节、证据和原因。

验收：覆盖 `5级/15级`、`50万/150万`、`50万/50万人`、逗号数字、中文量词、同义单位等测试。

#### P0-2 钩子生命周期

现状：只有 `open_loops`，没有关闭状态；历史钩子会持续回流，超过摘要窗口后又可能丢失。

实施：

- 引入稳定 `loopId`、`summary`、`status=open|resolved|deferred|abandoned`、首次出现章、最后推进章、目标回收章、解决证据。
- 章后交接增加 `opened_loops`、`advanced_loops`、`resolved_loops`，兼容旧 `open_loops`。
- 迁移旧摘要：为旧字符串生成确定性 ID，不破坏现有书库。
- 写前只注入仍为 open/deferred 且与当前任务相关的钩子；已解决项只在发生冲突时作为历史证据。
- 未解决钩子独立持久化，不依赖仅保留 40 章的 `memoryRoll`。

验收：钩子开启、推进、关闭、重新开启、旧数据迁移、40 章后仍保留未解决项均有测试。

#### P0-3 章后交接完整取样

现状：长正文摘要只取前 7000 字符，关系抽取只取前 5500 字符，章末反转和最终状态可能丢失。

实施：

- 构造 head + middle/key excerpts + tail 的确定性取样。
- 章末至少保留 2000–3000 字符；短章保持全文。
- 摘要 prompt 明确区分片段位置，避免模型误判顺序。
- 关系抽取同样保留尾部，并在必要时分块合并。

验收：超过阈值的章节仍能从章末提取钩子、地点、伤势、能力变化和关系变化。

#### P0-4 连续性警告真正回流

现状：`continuity_warnings` 被存储，但没有进入下一次写作上下文或 RAG。

实施：

- 将警告规范化为结构化记录：类型、严重级别、相关实体、证据、建议。
- 写前注入最近未处理的高风险警告。
- 摘要/RAG 文档包含警告，但权重低于 Canon 和已写正文。
- 支持作者确认“已处理/忽略”，防止永久污染。

验收：上一章产生的高风险警告可在下一章 `packForWrite` 中检索到，处理后不再重复注入。

#### P0-5 写作入口统一

现状：“按任务写/续本章”走完整 Harness；普通“续写/生成”只写正文，不自动交接。

实施：

- 明确两种模式：正式写章和草稿/局部续写。
- 正式模式统一走 Harness；普通生成完成后提示或自动进入交接阶段。
- 手工编辑后标记记忆/索引为 stale，并提供清晰的“重新交接”动作。
- UI 显示任务状态、交接状态、索引状态；禁止把仅生成正文误报为“本章完成”。

验收：所有正式写章路径最终达到 `done`；草稿路径清楚显示“未交接”。

#### P0-6 降级可见、连续性关键失败可控

现状：RAG 失败会静默继续写作。

实施：

- 记录检索失败、零命中、索引过期和 embeddings 回退原因。
- 提供 `warn` 与 `strict` 两级策略；strict 模式下连续性关键任务可阻止裸写。
- 写前 manifest 记录实际注入块、裁剪块、RAG 命中和缺失事实。

验收：失败不会无提示；strict 模式可可靠阻断，warn 模式可继续并留下日志。

### P1：生成前后质量保证

#### P1-1 任务相关 Canon 选择

- 保留少量全局硬事实，其余按任务实体、POV、节拍、钩子和 RAG 相关度选择。
- Canon 不再简单取类别排序前 36 条。
- 对当前任务出现的实体，优先覆盖身份、数值、位置、关系、能力、物品归属。
- manifest 显示省略数量和关键实体覆盖情况。

#### P1-2 Token-aware 上下文预算

- 提供中英混合 token 估算，而不是只按 JS 字符数。
- 为 system prompt、输出正文和上游包装预留安全空间。
- 使用块级最小配额：任务、主线、Canon、上章尾、当前正文尾、故事状态不得被后置块完全挤掉。
- 超限时采用逐块压缩/摘要，输出具体裁剪报告。

#### P1-3 写后连续性审查器

- 新增独立 JSON 审查请求，输入生成正文、任务卡、上章尾、相关 Canon、当前状态和 RAG 证据。
- 检查：Canon 冲突、重复事件、时间/地点/在场人物、能力越级、任务遗漏、禁区、钩子、人物声线和明显文风漂移。
- 审查结果分 `blocker|major|minor|info`，必须带证据片段。
- blocker/major 可进入局部修订；审查失败不得伪装为通过。

#### P1-4 可控自动修订

- 默认只修复明确违反硬事实的片段，不全文重写。
- 保留原文快照与修订记录。
- 修订后进行一次有限复检，避免无限循环。
- 用户可关闭自动修订或选择接受/拒绝建议。

#### P1-5 实体状态、时间线与位置表

- 从单一 `protagonistState/location/timeline` 扩展为按人物/物品/组织的状态记录。
- 状态包含位置、健康、能力、持有物、关系阶段、最后证据章。
- 时间线记录相对/绝对时间、事件顺序和旅行/间隔约束。
- 动态状态允许合法演进，不与静态 Canon 混为一谈。

#### P1-6 风格圣经与人物声线

- 保存叙述人称、时态、段落节奏、对白比例、禁用表达、专有标点和风格示例。
- 每个关键人物保留 voice 摘要与少量作者确认的对白样本。
- 写前按 POV 和出场人物选择性注入，避免占满上下文。
- 审查器检测明显声线漂移，但不以机械规则破坏创作自由。

### P2：检索、可观测性与真实评测

#### P2-1 检索增强

- BM25 保持零配置基线。
- embeddings 可用时扩大候选召回，而不是只重排已有少量词法命中。
- 加入相邻章窗口、实体别名、钩子 ID、关系邻居和时间邻近检索。
- 对 Canon、状态、原文、摘要分别设定配额，避免 Top-K 被单一类型占满。

#### P2-2 上下文 Manifest / 调试视图

- 展示本次请求实际使用的块、字符/token 估算、截断位置、Canon 选择、RAG 查询和命中。
- 标明数据最后更新时间、是否 stale、是否发生降级。
- 不在日志中暴露 API key。

#### P2-3 真实多章评测

- 建立固定故事圣经和任务集，运行 10–30 章多轮生成。
- 指标至少包括：硬事实冲突率、已解决钩子重复率、任务完成率、相邻衔接错误率、人物声线漂移、检索命中覆盖率。
- 区分确定性单元测试、mock 流水线测试、真实 Gemini 评测；真实评测需显式配置和费用确认。
- 保存每轮 prompt manifest、模型输出、审查结果和汇总报告，便于回归比较。

#### P2-4 发布与迁移

- 新字段提供向后兼容迁移，旧书首次加载不得丢正文或摘要。
- 同步 `novel-writer`、Tauri embedded UI、release UI。
- 更新 README、RAG/Harness 文档、版本与 changelog。
- 运行 Node、Python、Rust、UI 同步、版本检查和 release verification。

## 4. 实施顺序

1. 建立基线测试和迁移夹具。
2. 完成 P0-1 至 P0-6，先关闭已知数据正确性漏洞。
3. 完成任务相关 Canon 与 token-aware 装配。
4. 建立写后审查及有限修订闭环。
5. 扩展实体状态、时间线、风格圣经。
6. 增强检索和 manifest 可观测性。
7. 建立可选真实模型评测。
8. 全量回归、文档、UI 同步和发布验证。

## 5. 完成定义

只有同时满足以下条件，Goal 才能标记完成：

- 所有 P0/P1 条目完成并有自动化测试；P2 的真实模型评测框架完成，实际付费运行可由用户选择。
- 正式写章路径在无历史会话的情况下，能够从同一本书恢复完整的必要记忆。
- 已解决钩子不再进入下一章；长期未解决钩子不会因 40 章摘要窗口丢失。
- 数值 Canon 不再发生 substring 误判。
- 长章章末状态能被交接提取。
- RAG/预算/审查失败对用户可见，不再静默降级。
- 生成正文通过结构化连续性审查，或明确标记为未通过/待人工处理。
- 旧书迁移、保存、重启加载和索引重建通过测试。
- Node、Python、Rust、UI 同步与 release verification 全绿。
