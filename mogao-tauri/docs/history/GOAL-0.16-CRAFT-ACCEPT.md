# Goal 0.16 · 写后验收

**产品**：Inkwell / 墨稿  
**版本目标**：`0.16.0`  
**状态**：已交付  
**正式源**：只改 `novel-writer/`，验收后同步三套 UI。

## 0. 为什么是这一刀

0.15 把续写、修订、细纲和节奏收进同一闭环。模型仍可能对着细纲空转：场面没落地、整章转述、下一章看不见缺口。

本 Goal 把「像人写」从写前纪律补成写后可测：

```
Plan → Write → Craft Score（场面/对白/感官/套话）→ 风险账 → 下一章装配缺口
```

## 1. 交付

| ID | 项 | 完成标准 |
|----|----|----------|
| P0-1 | `scoreBeatCoverage` | 细纲地点/动作词是否出现在正文 |
| P0-2 | `lintHumanProse` | 对白过少、情绪总结、缺感官 |
| P0-3 | `chapter.craftScore` | 写章/修订后落盘，不另调模型 |
| P0-4 | 缺口回流 | 上章未落地场面进入下一章 `【上章未落地场面】` |
| P0-5 | 细纲 UI | 已落地 / 缺口边框；提示场面覆盖和对白比 |
| P0-6 | 评测 | `--score` 含 `beatSceneCoverage`、`dialogueRate` |
| P0-7 | 版本 | 全仓 `0.16.0` |

## 2. 不变量

- 不改 vault / book.json 权威字段语义（章上可增 `craftScore`）。
- 不引入打包器或 React。
- 写后验收是本地纯函数，不增加反代调用。

## 3. 明确不做

- 低覆盖自动整章重写（成本高、易盖稿）。
- 真 Worker 分析线程。
- 干净工作树正式包（仍需作者提交）。
