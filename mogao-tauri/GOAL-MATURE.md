# Goal · 一直迭代到成熟

**这是墨稿的常驻 Goal。** 每一期版本都是它的一次提交，不是另起炉灶。  
**成熟定义**：一个作者可以只靠「锁定主线 + 自动连写」，稳定产出读起来像人写的长篇，并且关窗不丢稿、写偏能纠、设定不会被幻觉污染。

产品：Inkwell / 墨稿  
当前基线：`0.19.0`（前端分层 + 编辑器热路径防抖/缓存 + 假保存冲突修复）  
正式源：只改 `novel-writer/`，验收后同步三套 UI。

---

## 1. 成熟长什么样（验收总表）

### 1.1 写作品质（像人写）

- [x] 写前有场面细纲，不对着任务卡空转
- [x] 开场类型不连章撞车；套话进风险账
- [x] 交接不能把无证据 / 顶撞锁定的事实写进 Canon
- [x] 自动连走审查 + 唯一命中局部修复
- [x] 按任务 / 续写 / 连写 / 修订 / 重写走同一套质量闭环
- [x] 重写选段、批注修订也走锁定/声线闸，失败不覆盖原稿
- [x] 按卷调节奏：闲章/高潮章场次数和字数不同
- [x] 评测可离线打分、可对比
- [x] 写后验收细纲场面是否落地；缺口回流下一章
- [x] 对白过少 / 情绪总结记入风险账，检查器看得见

### 1.2 作者控制

- [x] 锁定主线 / 禁区 / 风格圣经
- [x] 生成中锁切章切书；关窗 flush
- [x] 保存冲突双栏，不静默盖盘
- [x] 细纲可预览、可改再写
- [x] 连写中途改指令，下一章生效且不丢已写正文

### 1.3 日用可靠

- [x] 一书一夹 vault；原子写；空章不抹盘
- [x] 单实例；DPAPI 存 key
- [x] 写章细纲 UI 可单测（`write-ui.js`）；`app.js` 仍承担编排
- [x] 取数逻辑住在可单测模块，契约测试拦住算法回流 `app.js`
- [x] 长章打字不卡：全文打分防抖、上下文装配唯一入口且带缓存
- [x] 长篇分析块间让出事件循环
- [x] 会话 token 不长期挂在 URL（Cookie + 302）
- [x] 干净工作树正式包（0.19.0，`release/Inkwell.exe` 与 ui/manifest 对齐）

### 1.4 明确非目标

云同步、多人协作、React 重写、完整移植 G6、把 Python 调试服当生产、替作者决定主题立场。

## 2. 迭代纪律

1. 一次尽量关掉多格，但每格必须可测。
2. 先质量入口，再工程债。
3. 同一条质量闭环。
4. 能单测的算法不进 `app.js`。
5. 版本单调递增。

## 4. 本期 0.19

见 CHANGELOG 0.19.0。0.18 交付后自查发现四类问题，本期收口：

1. **前端结构债**：`app.js` 4800 行里混着筛选排序、关系图取数、撤销状态机这些本该单测的算法，改一处要靠人肉读全文。本期抽出三个无 DOM 的模块并加契约断言。
2. **热路径**：`craftScore` 逐键扫全章、`packForWrite` 在一次生成里重复装配，长章打字发涩。本期改为防抖 + 唯一入口缓存，并保证落盘前补齐。
3. **0.18 自身的洞**：停止被包成交接失败；只补相邻上一章；补交接会在后台改写作者没在看的那一章；无证据的合成问题被送进补丁引擎空跑。
4. **假保存冲突（阻断级）**：保存自己会把章节文件的磁盘 mtime 推新，而客户端一直拿加载时的旧 mtime 比对，于是同一次会话里第二次改同一章就弹出「磁盘版本保护」、正文存不进去。本期由后端在保存响应里回传每章基线、客户端保存后换基线，冲突章除外。这条是靠浏览器回归撞出来的，说明「连改两次同一章」这种最日常的动作以前没有端到端覆盖。

正式 exe 已打出：`release/Inkwell.exe` + `ui/` + `manifest.json` 均为 0.19.0。
