# Inkwell（墨稿）详细使用说明

**版本概念**：客户端 **0.19.0**（前端分层、长章打字不卡、写前补齐前文所有待交接章）  
**英文名**：Inkwell · **中文名**：墨稿  
**正式程序**：`Inkwell.exe`（同目录需保留 `ui\` 文件夹）

---

## 1. 它是什么

Inkwell 是本地优先的 **AI 小说工作室**：

- **一书一夹** 书库（可对接 Obsidian / 资源管理器）
- **策划 → 任务板 → 自动/半自动连写**
- **跨章连贯**：故事线、细节设定锁定、上章衔接、本地 RAG 检索
- **写章 Harness**：检索 → 写正文 → 章后交接 → 关系 → 再索引
- **叙事分析**：切章分块、关系图谱、档案与时间线

模型默认走 **OpenAI 兼容接口**（你的 gemini2api / 反代），例如 `gemini-3.6-flash`。

## 2. 安装与启动

### 2.1 目录结构（发布包）

```text
release/
  Inkwell.exe          ← 双击这个
  ui/                  ← 必须与 exe 同目录（前端）
  使用说明.md / .txt
  （可选）墨稿-Tauri.exe  ← 旧名兼容，内容同类
```

### 2.2 启动

1. 双击 **`Inkwell.exe`**
2. 首次会连本地内嵌 API（自动带 token），并打开/创建书库
3. 默认书库路径常见为：
   - 曾配置过：设置文件里的 `vaultPath`
   - Release 未配置时：`%LOCALAPPDATA%\Inkwell\vault`
   - Debug 未配置时：源码目录 `mogao-tauri\vault`

### 2.3 重新打包（开发者）

```bat
cd mogao-tauri
build-release.bat
```

会同步前端、跑测试、编译，输出新的 `release\Inkwell.exe` + `ui\`。

> **不要用** 旧的 Python `novel-writer/server.py` 当事生产后端（DEBUG ONLY）。

## 3. 首次必做：设置

点右上角 **⚙ 设置**。

### 3.1 模型连接（连写必需）

| 项 | 说明 | 建议 |
|----|------|------|
| **Base URL** | OpenAI 兼容根地址 | 你的反代，如 `https://xxx/v1` 或本机 gemini2api |
| **API Key** | 鉴权密钥 | 填你的 key，关设置时由 Windows DPAPI 加密保存 |
| **模型** | 写章/策划用模型 | 如 `gemini-3.6-flash` |
| 上下文预算 | 单次写章 prompt 字符上限 | **≥ 14000～16000** |
| 输出预算 | 单次章节正文最大输出 tokens | 默认 3500；出现“输出上限停止”时适当提高 |
| 上章文末衔接字数 | 带上章正文尾 | 默认约 1800 |
| 每章目标字数 | 提示模型篇幅 | 默认 2000 |
| 启用 Harness | 检索→写→交接流水线 | **建议开** |
| 启用本地混合 RAG | BM25 检索旧文/设定 | **建议开** |
| RAG 向量重排 | 调 `/v1/embeddings` | 反代支持再开，否则关 |
| RAG Top-K | 检索条数 | 默认 8 |
| 重建 RAG 索引 | 手动重建 | 旧书/改设定后可点 |

点 **测试连接** 确认 API 可用。  
**改完 key/主题后务必点关闭保存**（会写磁盘，见下节）。

### 3.2 外观主题

- **柔纸** / **墨夜** / **青简**  
- 切换后会持久化。

### 3.3 配置存在哪

| 存储 | 路径/方式 |
|------|-----------|
| **普通配置（重启不丢）** | Release：`%LOCALAPPDATA%\Inkwell\mogao-settings.json`；Debug：源码目录 `mogao-settings.json` |
| **API Key** | Release：`%LOCALAPPDATA%\Inkwell\api-key.dpapi`，仅当前 Windows 用户可解密 |
| 缓存 | 浏览器/WebView localStorage；不保存 API Key |

设置页可看到 `settingsFile` 等引擎信息。

### 3.4 书库

- **打开库… / 新建库…**：选择小说根目录（其下有 `books/` 或会被初始化）
- 每本书一个文件夹，例如：`书库/books/书名/`

## 4. 界面总览（四个顶栏入口）

| 一级入口 | 用途 |
|----------|------|
| **写作** | 章节列表、正文、叙事脉络、故事检查器与统一 AI Composer |
| **故事** | 二级入口为 **策划 / 主线与任务 / 人物关系**，集中管理任务、Canon、伏笔、连续性和关系图谱 |
| **资料** | 类 Obsidian 文件树 + 编辑/预览；跨书搜索、快照与其他资料操作也从这里进入 |
| **分析** | 全书切章分块、关系图谱、人物档案、时间线与摘要报告 |

当前书名是左上角的 **书库抽屉入口**。抽屉保留筛选、新建与快照；点击遮罩、按 `Esc` 或切换书目都会关闭。右上角扳手是书库工具，齿轮是设置。

**快捷键（常用）**

- **Ctrl/Cmd+1～4**：依次切换 **写作 / 故事 / 资料 / 分析**  
- **Alt+1～3**：在故事中心切换 **策划 / 主线与任务 / 人物关系**  
- **Ctrl/Cmd+S**：写作页保存当前作品；资料页保存当前文件  
- 生成中会 **锁定切书/切章**，避免串稿；可点 **停止**

### 4.1 侧栏折叠

多数侧栏标题旁有 **« / »**：

- 文件树、写作左右栏、主线/策划/图谱/分析侧栏  
- 折叠成窄条后 **再点可展开**  
- 折叠状态会写入 `uiState` 并持久化

1200px 以下故事检查器改为右侧抽屉；1050px 以下章节列表也改为抽屉，不再挤窄正文。写作页的 **专注** 模式会隐藏导航和两侧面板，只保留正文、章节状态与退出入口。

## 5. 推荐创作流程（从 0 到连写）

### 步骤 A · 建书 / 打开书

1. **＋ 新书** 或选左侧书库已有书  
2. 或 **导入示例** 熟悉流程  
3. 左侧书库可筛选、刷新、创建快照

### 步骤 B · 策划（「故事 → 策划」）

1. 填写作意向 / 题材  
2. **一键全自动策划**（或分步：立项 / 世界 / 人物 / 主线）  
3. 生成：书名候选、世界观、人物关系、**任务板**（每章 goal/beats/禁止/钩子）  
4. 确认后进入 **故事 → 主线与任务**

### 步骤 C · 锁主线（「故事 → 主线与任务」）— 强烈建议

1. 填写并锁定 **logline**（最高优先级）  
2. 填 **全局禁区**、**必须兑现**  
3. 可勾选锁定世界/人物/脊柱，避免重跑策划冲掉  
4. 检查任务表：标题、目标、禁止项；可编辑单卡  
5. 右侧查看：**故事线 / 细节设定 / 滚动摘要**（写过章后才有丰富内容）

### 步骤 D · 写章（「写作」入口）

**单章**

1. 从左侧选择章节；章节头会独立显示 **字数 / 保存状态 / 章后交接状态 / 更多操作**。  
2. 先读正文上方的 **叙事脉络条**：本章任务、POV、开放伏笔、连续性风险和上下文健康度都可点击打开对应检查器。  
3. 在底部 Composer 选择一种方式：**按本章任务写作 / 从当前位置续写 / 重写选中段落 / 根据批注修订**。主按钮会随模式改名。  
4. “根据批注修订”要求在指令框写清修改意见；模型完整成功后才替换整章，失败或停止会保留原稿。“重写选中段落”也采用相同的成功后提交保护。  
5. 生成期间会依次显示 **装配记忆 / 请求模型 / 连续性审查 / 章后交接**；只有运行期间显示停止按钮。  
6. 手工修改或修订后会显示 **待交接**。可从章节头的 **更多 → 执行章后交接** 更新摘要、关系与故事记忆。

右侧 **故事检查器**分为“本章任务 / 连续性 / 故事记忆”。故事记忆中的 **跳到故事中心** 会直接打开主线页的滚动摘要分组；原始 token 与块级 Manifest 收在“技术详情”中。

**自动连写**

1. 确认已锁主线、API 可用  
2. 点 **自动连写**  
3. 按任务顺序：未 `done` 的会依次执行  
4. 单章失败会 **停止** 并保留状态（可稍后重试）  
5. 章间有暂停（默认约 1.2s，限流时可在配置里加大）

**任务状态机（断点续跑）**

```text
pending → writing → written → digested → done
```

- `written`：正文已有，再连写会 **跳过写章**，只补摘要/交接  
- `done`：默认跳过  
- 失败时看状态栏 / 弹窗里的 `lastError`（如 429 限流）

## 6. 跨章连贯是怎么工作的（理解即可）

**每一章对模型都是新对话**，不靠同一条 chat 历史。

### 6.1 写前（让模型「读到进度」）

一次 prompt 里尽量带上：

1. 锁定主线 / 禁区  
2. **故事线位置**（上章概要、下一推进方向、任务线）  
3. **细节设定文档**（如 `王大锤.粉丝数=50万`，锁定不可乱改）  
4. **RAG 检索**（BM25 从旧正文/摘要/设定里捞相关片段）  
5. **上章文末**原文（局部衔接）  
6. 本章 **任务卡**  
7. 开放钩子、人物、世界观等（预算内）

### 6.2 写后（为下一章存档）— Handoff

另一次（较短）调用抽出 JSON，写入：

| 产物 | 磁盘位置（书目录下） |
|------|----------------------|
| 章节正文 | `章节/*.md` + `book.json` |
| 滚动摘要 | `记忆/digests.json` |
| 细节设定 | `记忆/canon.json`、`记忆/细节设定.md` |
| 故事线 | `记忆/storyline.json` |
| 出场 | `记忆/appearances.json` |
| 关系图 | `关系/graph.json` |
| RAG 索引 | `记忆/rag-index.json` |
| 锁定 | `锁定/locks.json` |
| 策划 | `策划/*` |

**Harness 流水线（默认开）**

```text
Retrieve → Write → Handoff(摘要+设定+故事线+出场) → Graph → Reindex
```

## 7. 工作区用法

1. 左侧文件树浏览 `章节/`、`策划/`、`记忆/` 等  
2. 可新建笔记/文件夹、重命名、删除  
3. 编辑 / 分栏 / 预览；**Ctrl+S** 保存  
4. 外部用 Obsidian 改同一目录时，可 **↻ 重载** 或依赖轮询刷新  
5. **📂 打开目录** 用资源管理器打开当前书

注意：生成中请勿乱切书；工作区与 vault 以磁盘为准。

## 8. 关系与分析

### 关系模式

- 查看/编辑人物关系图  
- 写章交接会 **增量合并** 关系  

### 分析模式

1. **从本书章节载入** 或粘贴全文  
2. **识别章节** → **开始分析**（可暂停/续跑）  
3. 产物写入书下 `分析/`，并可能更新 `关系/graph.json`  
4. 进度使用作者语言显示 **识别完成 / 正在分析 / 正在聚合结果 / 分析完成**  
5. 默认看摘要、人物档案和关系时间线；原始 Markdown/JSON 在高级视图

- **创建快照 / 快照列表**：`book.json` 历史，可恢复

## 10. 常见问题

### Q：重启后 API Key / 主题没了？

- 使用 **0.19.0+**，关设置时会事务写入普通配置，并把 API Key 写入 DPAPI 密文  
- 确认设置页 `settingsFile` 路径可写  
- 重新打包后请用新 `Inkwell.exe` + 新 `ui\`

### Q：自动连写卡在某一章？

- 看是否 **HTTP 429**（反代限流）→ 加大章间暂停、减并发、等额度  
- 状态若是 `written`：再点连写会只补摘要  
- digest 失败不会丢已写正文  

### Q：第 2 章和前一章对不上 / 数字乱变？

- 确认 **Harness + RAG 开着**，预算够大  
- 写完后要完成 **摘要/交接**，细节才会进 canon  
- 可打开 `记忆/细节设定.md` 人工改锁定项  
- 旧烂 digests 可清理后从断点只补摘要，或重建 RAG 索引  

### Q：Inkwell.exe 和 Inkwell-new.exe？

- **只用 Inkwell.exe**；`Inkwell-new` 是历史临时副本（应已删除）  

### Q：限流 / 很慢？

- 每章至少：写正文 + 交接（+ 可选关系）= 多次 API  
- 调大 `autoChapterDelayMs`、关 embeddings、略降 `ragTopK` / 预算  

### Q：Python 服务？

- **不要** 当事生产；正式只用 **Inkwell.exe**

## 11. 安全提示

- API Key 存在用户目录的 DPAPI 密文 `api-key.dpapi`，不要复制、提交或与设置目录一起公开  
- 升级前遗留的 `mogao-settings.json` 或备份可能仍含明文 Key；确认迁移后请更换曾泄露的 Key，并妥善清理旧副本  
- 本地 API 带会话 token，一般仅本机环回  
- 书稿在本地 vault，自行做好备份
